# 内容与展示规则

文中路径相对于仓库根目录。

## 图片数量过滤

清理后的原始主帖正文超过 **20 个 `<img>` 标签**时，过滤整篇文章；恰好 20 张保留。重复图片 URL 仍按标签计数，不使用数据库中可能陈旧的图片计数。此规则先于“防水图”和文末图片隐藏规则执行，隐藏图片不能绕过数量限制；采集器不下载图片。

新采集和已有归档使用同一规则。运行 `build` 会重新筛选已有文章，移除命中文章的列表、搜索数据和文章页；现有发布流程会在下次成功发布时按删除清单清理服务器历史版本的对应页面。被屏蔽正文保留在非公开数据库中，仍受 30 天保留规则约束。

## 采集与公开展示

技术讨论区采集器与静态阅读网站。首次补采启动前 **30 天**的主帖，此后由 GitHub Actions **每小时第 17 分钟**运行，按原帖发布时间滚动保留最近 **30 天**。配置在 `config.toml`，没有管理后台。

**按标题和正文黑名单排除整篇帖子，不识别图片内容。图片只保留原链接，采集器不请求、不保存、不上传图片。** 浏览器阅读文章时会直接请求原图地址，外链可能因防盗链、失效或 HTTPS 页面加载 HTTP 图片而无法显示。

文章页不显示图片外链加载提示。构建时移除原文末尾的“赞(数字)”计数（兼容跨标签、空白及中文括号），同步更新列表摘要和搜索正文；正文中间的相同文字保留。此处理先于文末图片隐藏判断，适用于已有归档，不修改数据库原文。

主帖正文出现“防水图”时，公开页面屏蔽该文章的全部图片，并从正文和列表摘要中移除“防水图”三个字，保留其余文字，隐藏图片数量和图片加载提示。支持文字跨 HTML 标签或以实体编码出现。该规则也适用于已经采集的文章，重新运行 `build` 即可生效；数据库中的原始归档不变。

正文至少包含 **200 个非空白字符**，且**所有图片都在正文末尾、图片后没有文字**时，在文章通过图片数量过滤后，公开页面也会屏蔽全部图片。空白、换行和图片外层的链接或容器不影响判定；如果正文开头或中间有图片，或图片后有说明文字，则不应用此规则。该规则同样适用于已有归档，隐藏后同步移除图片数量和加载提示，不修改数据库原文。

每个页面提供搜索框，可搜索全部已收录文章的**标题或完整正文**，不限于当前列表页或月份，也不限于摘要。按关键词包含关系匹配，忽略大小写、空白及全角/半角差异；不搜索图片地址或 HTML 属性。搜索结果沿用文章发布时间倒序，支持分页。关键词与页码保存在 URL 中，可刷新、分享或使用浏览器前进后退。

最近一次爬取成功新增的文章，会在列表、月份归档、文章页和搜索结果的标题旁显示亮黄色底、红色文字的 **NEW** 标签。下一次完成爬取后，上一批标签移除，仅标记该次新增文章；没有新增则全部移除。部分帖子获取失败时仍标记本次成功收录的文章；若列表获取失败、爬取未完成，保留上一批标记。只执行 `build`、更新黑名单或清理发布不切换批次。标记随 SQLite 状态保存；升级前已有文章不会自动标新，从下一次爬取开始记录。

首页、月份归档和搜索结果均显示当前页、总页数、页码按钮及“跳至”输入框；页数较多时省略中间页码，可输入任意有效页码跳转。每页条数由 `site.page_size` 控制。搜索及输入页码跳转需要启用 JavaScript。

搜索在浏览器本地进行，无需后端或额外修改 Caddy。构建时生成 `assets/search-index.js`，仅在打开搜索页时加载，包含通过黑名单、图片数量和 30 天保留规则的文章标题、公开正文纯文本及列表字段。下架文章后会同步使历史版本的全文搜索数据失效，保留新版本索引；数据库原文不变。首次搜索需要下载全文数据，文章较多时加载时间及浏览器内存占用会相应增加。

## 本地关键词与来源

关键词统一维护在 `blacklist/keywords.txt`，包括原配置、旧 Block 文件、补充的色情和广告话术，以及原第三方词库中色情、广告两类规则的本地副本。按**标题或正文包含词**匹配，任一命中就屏蔽整篇。

第三方 Git 子模块已移除，本地运行和 GitHub Actions 都直接读取仓库内的词库，不再拉取或自动更新外部词库。新增规则直接修改 `blacklist/keywords.txt`，也可通过网页 `Block` 复制划词后打开 GitHub 文件编辑页。

原说明引用的 `blacklist/SOURCES.md`（迁入来源、版本、标点处理）和 `blacklist/licenses/`（许可证与版权声明）当前不在工作区中；维护迁入词库时需核实这些材料，不能推断其内容。

## 配置与采集行为

- `source.list_url`：指定技术讨论区列表地址。只接受该来源的帖子请求，不跟随重定向到其他地址，不获取其他版块的置顶链接。
- `source.request_interval_seconds`：配置请求间隔，同时遵守 robots.txt 的 Crawl-delay / Request-rate 中更严格的限制。本次验证源站要求每 10 秒至多 1 个请求。
- `crawl.initial_days`：数据库首次建立时固定补采起点；此后还会按每轮运行时间执行最近 30 天保留规则，超过 30 天的帖子不再展示或补采。
- `crawl.recent_pages_per_run`：每轮近期列表扫描预算。第一页每次刷新，其余分页按游标继续扫描，直到最后回复时间越过回看范围后重新开始。
- `crawl.overlap_hours`：近期列表回看时间，默认 48 小时；去重依靠帖子 ID，不依赖标题或一次易变的列表位置。
- `crawl.backfill_pages_per_run`：每轮历史列表扫描预算；断点保存到 ECS 上的状态文件。按最后回复时间判断历史扫描边界；不能因为一页主帖创建日期较旧就提前结束。
- `crawl.max_posts_per_run`：每轮主帖获取预算；发现的合格链接会先保存，再分批获取。默认 60 篇，未完成任务下一轮继续，不会标成已完成。
- `crawl.max_attempts`：主帖最大跨轮重试次数，默认 3；耗尽后仍保留错误记录。人工重试：`python -m forum_archive crawl --retry-failed`。
- `blacklist/keywords.txt`：本地标题或正文包含词，一行一个；会先统一全半角、英文大小写，去掉空白和零宽格式字符。配置中的 `filter.blocked_keywords` 仍兼容读取，当前配置已迁出该列表。
- `filter.blocked_patterns`：分别作用于规范化标题和正文的正则表达式。当前启用 `\[\d+v\]`，标题或正文出现 `[24V]` 这类“中括号内数字＋V”标记即屏蔽整篇，兼容大小写、全角字符、空白和跨标签文字；不匹配 HTML 属性或图片 URL，也不匹配无中括号的 `24V`。已有归档在构建时重新筛选。无效正则会在启动时报告。
- `filter.keyword_files`：可选的额外本地逐行词库文件，路径相对于配置文件目录；当前配置不使用。缺失时报告文件路径，不会静默跳过。
- `site`：网站名称、说明和每页数量。
- `storage`：SQLite 状态与生成网站的目录，路径相对于配置文件所在目录。

先在列表页筛选标题；获取正文后再检查完整标题和全文，不限于摘要。正文使用清理后 HTML 提取出的文字匹配，支持跨标签和 HTML 实体，不匹配标签属性、图片地址或链接目标地址。只提取楼主主帖，不采集楼内回复、头像、签名、视频与附件。清理正文中的脚本、事件属性、表单和嵌入页面。识别 `ess-data` / `data-original` / `data-src` 等原图属性，去掉占位图属性，不发出图片请求。

正文或图片数量规则命中的帖子保留在非公开数据库中，以便后续重新应用黑名单，避免每轮重复抓取；不生成公开文章页，仍按 30 天保留规则清理。删除对应规则后，未命中其他规则且未过期的帖子可恢复收录。

修改黑名单后运行 `build` 即可重新筛选现有文章并切换到新的静态版本，不必重新抓取。命中新增规则的旧文章会从首页、归档和文章页中移除，同时删除本地历史生成版本中的对应文章 HTML。发布到 ECS 后也会删除远端 `releases/release-*/posts/<帖子ID>.html` 中的命中页面。帖子 ID、屏蔽状态和数据库归档保留，避免重复收录；移除规则后可以重新生成页面。

```powershell
.venv/Scripts/python.exe -m forum_archive build
```

每次生成网站时，也会清除原帖发布时间早于“当前时间减 30 天”的正文、摘要和图片计数，状态改为 `expired`，删除对应的当前及历史版本文章 HTML，并重新生成列表与月份归档。恰好 30 天的帖子保留；删除使用原帖发布时间，不使用抓取时间、回复时间或文件修改时间。帖子 ID 与时间等元数据保留用于去重，旧帖被回复顶起也不会重新收录。

部署后，每小时定时任务和手动任务都会先清理发布，再访问源站采集内容；push 仅恢复服务器数据库、应用过滤及 30 天保留规则、重新发布并清理服务器文章页。需要立即采集时，在 GitHub **Actions → Hourly archive → Run workflow** 中选择 `master` 并运行，无需额外选项。需要先把本次代码推送到默认分支。该流程不要求在本机配置 ECS 凭据，使用仓库现有部署 Secrets。

## 网页划词编辑黑名单

在文章标题、正文或列表摘要中用鼠标选中文字，会弹出一个 `Block` 按钮。点击后复制关键词，并打开 GitHub 中固定文件 `blacklist/keywords.txt` 的编辑页：

1. 登录有仓库编辑权限的 GitHub 账号。
2. 在文件末尾另起一行，粘贴关键词，保留已有内容。
3. 点击 GitHub 的 **Commit changes** 保存。若仓库允许，直接提交到 `master` 即可；分支保护要求审核时，按 GitHub 提示操作。

这是纯静态功能，不创建 Issue，不自动创建 PR，不需要 OAuth 服务、访问令牌或额外的 Actions 权限。若浏览器阻止复制，会弹出包含关键词的对话框供手动复制。GitHub 编辑链接不能自动将划词追加到已有文件，因此需要在末尾粘贴一行。

新增词统一追加到 `blacklist/keywords.txt`，不再逐词新建文件；原有配置词和旧哈希文件中的词已合并到此文件，加载器仍兼容配置及其他 `blacklist/*.txt`。变更进入 `master` 后触发清理发布，应用新规则及 30 天保留规则、删除命中或过期的旧文章页面，不采集新帖；新内容由下一轮定时任务采集。关键词同时匹配**标题和正文**，已有文章也会按全文重新筛选。

`config.toml` 的 `[site]` 中配置 `github_repository = "owner/repo"` 和 `github_branch = "分支名"`。当前为 `duiniuluantanqin/last30days`、`master`；仓库留空会隐藏此功能。

选择长度限制为 1–80 个字符，换行合并为空格；已被现有包含词规则覆盖、包含控制字符或超长的选词不显示按钮。点击空白处、滚动或按 Escape 可关闭。普通 HTTP（包括公网 IP 地址）和 HTTPS 都支持；复制不依赖 Web Crypto 或仅在安全来源提供的 Clipboard API。

**Caddy 参考配置（由用户自行维护）：** 在 `Content-Security-Policy` 中增加 `script-src 'self'`，参考 `deploy/Caddyfile.example`。这里只允许加载本网站的脚本，不需要放开内联脚本或 GitHub API 请求。此说明不授权自动修改服务器配置。用户自行修改 Caddy 配置后验证并重载；本地预览服务修改代码后也应重启。

`backfill_complete` 表示历史列表发现阶段已完成，不代表所有正文都已取得。应同时检查 `pending` 数量和错误记录。列表变动、来源访问限制及删除的原帖都可能影响覆盖范围；不会宣称恢复不可访问的内容。现阶段保存首次取得的正文，不自动追踪原帖之后的编辑和删除。
