# 网页提交的黑名单关键词

网页划词后点击 `Block`，会打开已填好关键词的 GitHub Issue。提交 Issue 后，Actions 自动从默认分支创建独立分支，在 `blacklist/keywords.txt` 末尾追加一行并创建 PR，无需手动编辑文件，也不为每个词创建独立文件。

PR 由仓库作者审核并手动合并，之后关键词才进入默认分支（当前为 `master`）并生效。网站不保存令牌，不会自动合并。首次启用需开启 Issues 并允许 Actions 创建 PR，配置方法见根目录 `README.md` 的“网页划词提交黑名单 PR”。

本地关键词集中维护在 `keywords.txt`，原 `config.toml` 的 `filter.blocked_keywords` 与旧 Block 哈希文件中的词已迁入，重复词按匹配时的规范化规则去重。该文件也包含补充的色情、招嫖引流和广告话术，使用每行一个关键词的格式；不要添加分类标题或注释行，这些内容也会被当作关键词。

PR 合并后，流水线会将本地词和上游色情、广告词库合并应用，并重新筛选已经收录的文章，删除服务器上的命中文章页面。加载器仍兼容读取其他 `.txt` 文件及配置中的 `filter.blocked_keywords`，但新增本地词统一追加到 `keywords.txt`。空行忽略，本说明文件不会作为关键词读取。

所有词均匹配标题和全文的包含关系，不分析语境。原有“奶”“学生”等宽泛词也已保留；若误屏蔽正常文章，应在本文件中调整对应词，同时留意上游词库是否也包含该规则。
